# Portfolio — notes for agents

Vite + React 19 + TypeScript + Tailwind CSS v4 (shadcn/ui configured). The
approved design is final: changes must not alter rendered output unless that
is the explicit task.

- `npm run dev` — dev server (client-rendered).
- `npm run build` — image variants, typecheck, client + SSR build, then
  `scripts/prerender.mjs` writes static HTML for every route, `404.html`,
  `robots.txt` and `sitemap.xml` into `dist/`.
- `npm run preview` — serves `dist/` with Vercel-style clean URLs and 404s.

Conventions:

- Content lives in `src/data/*` (typed in `src/types`); per-route `<head>`
  tags in `src/lib/seo.ts`.
- Styles: `src/styles/index.css` imports every stylesheet in a fixed order
  that preserves the original cascade. Component styles sit next to their
  component and are in Tailwind's `components` layer. Each capability scene
  has its own stylesheet (`src/components/services/*-scene.css`); the shared
  stage, canvas, cursors and pause control are in `service-stage.css`.
- Images: use `@/components/ui/Image` with `/public` paths; resized WebP
  variants are generated by `scripts/optimize-images.mjs`.
- Motion language is "drawn, then built". Defining entrances use the draft
  system: mark an element `data-draft="set|frame|ink"` and
  `useDraftOnView` + `src/styles/draft.css` handle it (frames also need a
  `.draft-spec` child). Supporting copy settles via timelines declared in
  `src/data/scrollTimelines.ts` and run by `src/lib/scroll-timeline.ts`.
  Easing and duration tokens live in `src/styles/tokens.css`.
- Commit messages use Conventional Commits: `feat:`, `fix:`, `refactor:`,
  `style:`, `docs:`, `chore:` plus a short imperative summary.

Branches:

- `main` is the only long-lived branch, and Vercel deploys every commit on it
  to production. Never commit or push to `main` directly, and never delete
  it.
- Work on a short-lived branch cut from an up-to-date `main`
  (`git pull --ff-only` first), named `feat/`, `fix/`, `refactor/`, `style/`,
  `docs/`, `chore/` or `ui/` plus a short slug. Never reuse or overwrite an
  existing branch; carry uncommitted work over rather than discarding it.
- Stage only the files the task changed. Push with `-u` once the first commit
  has been reviewed and lint and the build pass.
- Changes reach `main` through a pull request into `main`. Never merge one
  without the owner's approval.
- After a merge: confirm the pull request is merged, switch to `main`, run
  `git pull --ff-only` and `git fetch --prune`, then remove the local branch
  with `git branch -d`. GitHub already deletes merged branches on the remote;
  remove one by hand with `git push origin --delete <branch>` only after
  checking it holds nothing missing from `main` and has no open pull request.
- If `git branch -d` refuses, for example after a squash merge, check the
  branch's pull request and diff against `main` before deleting anything.
  Never force-delete, force-push or rewrite history as routine cleanup.
